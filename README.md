# FSK Packet Modem — GNU Radio

This project implements a **binary FSK (Frequency Shift Keying) packet modem** in GNU Radio using separate transmitter and receiver flowgraphs. The transmitter reads text data, converts it into bits, repeats each bit according to the configured baud/sample-rate relationship, and uses a VCO-based frequency-shift mechanism to generate an FSK complex waveform. The receiver reads the generated complex waveform from a file, performs quadrature demodulation, binary slicing, bit-rate reduction, byte repacking, and finally writes the recovered data to an output file.

## Project Files

| File | Purpose |
|---|---|
| `FSKMODEMTX.grc` | FSK packet transmitter |
| `FSKMODEMRX.grc` | FSK packet receiver |
| `input.txt` | Transmitter input text file referenced by the flowgraph |
| `data` | Complex FSK sample file produced/used in the test flow |
| `result.txt` | Recovered byte output referenced by the receiver |

## Modulation Parameters

- **Sample rate:** 48 kHz
- **Baud rate:** 1200 baud
- **Mark frequency:** 1200 Hz
- **Space frequency:** 2200 Hz
- **Frequency separation:** 1000 Hz
- **Calculated center frequency:** 1700 Hz
- **Samples/bit:** 48
- **FSK deviation variable:** `abs(mark-space)` = 1000 Hz

## Transmitter Flow

`input.txt → bit repacking → bit repetition → byte-to-float → VCO control → complex FSK → throttle → data`

The transmitter also displays the generated complex waveform using a Qt GUI time sink and monitors the real component through an audio sink.

## Receiver Flow

`data → quadrature demodulator → DC/offset correction → binary slicer → decimation → bit/byte repacking → result.txt`

The receiver contains additional Qt GUI time-domain displays for inspecting the received complex waveform, demodulated signal, and recovered bit stream.

## Important Note

The current GRC files implement a **file-based FSK testbed** rather than a direct RF/USRP transmitter-receiver chain. The transmitter writes complex samples to a file, while the receiver reads complex samples from a file. The two flowgraphs also contain GNU Radio Virtual Source/Sink blocks, but their stream IDs are different (`t2` in the transmitter and `r1` in the receiver), so they do not form a direct virtual connection between these two flowgraphs.

## Expected Result

When the complex FSK sample file generated by the transmitter is supplied to the receiver in the expected format, the receiver demodulates the two FSK frequency states into binary data and writes the recovered bytes to `result.txt`. The GUI sinks provide visual confirmation of the waveform and recovered bit stream.

> **Safety:** This project is currently file-based and does not contain an RF hardware source/sink. If it is later extended to an SDR transmitter, perform RF experiments only in an authorized and controlled setup.
